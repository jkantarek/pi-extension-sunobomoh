# Implementation Plan: Sunobomoh Watch Engine

**Branch**: `001-sunobomoh-watch-engine` | **Date**: 2026-05-07 | **Spec**: natural-language brief
**Input**: User feature description — programmatic multi-source event watcher with centralized JSONL state,
multi-tag outcomes, hydration pipeline, Active Record-style callbacks, and hourly LLM steering.

---

## Summary

Sunobomoh is a **pi coding-agent extension** that provides a programmable watch-and-react engine.
Arbitrary data sources (GitHub, Gmail, Slack, browser tabs, filepaths, etc.) are connected via a
`WatcherDefinition` plugin contract. Events flow through an opt-in hydration pipeline, are tagged
with a multi-tag system, and written to an append-only JSONL state store that is the single source
of truth for the extension. A scheduler drives watchers every _N_ minutes (default 10). An hourly
steering step—optionally LLM-assisted—promotes or demotes entries into/out of the `needsAttention`
bucket. Each watcher carries a configurable side-effect array modelled after Active Record callbacks
(`before_watch`, `after_watch`, `before_hydrate`, `after_hydrate`, `before_steer`, `after_steer`).

## Architectural Decisions (summary — details in research.md and architecture-review.md)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| State persistence | Append-only JSONL | Matches pi session format; zero deps; easy tail/grep |
| Watcher plugin model | TypeBox-validated plugin objects (not classes) | Composable, testable, no inheritance |
| Hydration ordering | Ordered array, serial execution | Predictable; avoids race conditions |
| Side-effect model | Active Record callback phases on each watcher | Familiar, self-contained, per-watcher config |
| Steering intelligence | Rule-based default + opt-in LLM call via pi.sendUserMessage | Usable offline; LLM adds value when available |
| URI scheme | RFC 3986 with custom schemes (`github:`, `gmail:`, `slack:`, `file:`, `browser:`) | Not HTTP-limited; serializable as string |
| Tag outcomes | Typed per TagDefinition via TypeBox schema | Enables per-tag validation without generics explosion |
| Scheduler state | `pi.appendEntry()` per-run record | Survives pi session restarts; queryable |
| Coverage strategy | Pure functions + dependency injection | Eliminates need for mocks; every path reachable |

## Lifecycle Diagram

```
pi session_start
  └─► Scheduler.start()
        │
        every N minutes (default 10):
        │
        ├─► for each WatcherDefinition:
        │     ├─► SideEffectExecutor.run('before_watch', ctx)
        │     ├─► WatcherRunner.run(watcher, config, signal)
        │     │     └─► raw events → coerce to StateEntry[]
        │     ├─► SideEffectExecutor.run('after_watch', ctx)
        │     │
        │     ├─► for each HydratorDefinition in watcher.hydrators:
        │     │     ├─► SideEffectExecutor.run('before_hydrate', ctx)
        │     │     ├─► HydrationPipeline.run(hydrator, entries, signal)
        │     │     └─► SideEffectExecutor.run('after_hydrate', ctx)
        │     │
        │     ├─► TagRegistry.applyTags(entries)
        │     └─► StateStore.appendBatch(entries)
        │
        every 60 minutes (steering):
        │
        ├─► SideEffectExecutor.run('before_steer', ctx)
        ├─► Steerer.run(store, config)
        │     ├─► score each recent entry (rule-based)
        │     ├─► [optional] LLM call via pi.sendUserMessage for complex cases
        │     ├─► promote high-score entries → needsAttention = true
        │     └─► demote stale entries → needsAttention = false
        ├─► StateStore.appendSteeringRun(result)
        └─► SideEffectExecutor.run('after_steer', ctx)

pi session_shutdown
  └─► Scheduler.stop()
```

## Pi Extension Integration Points

|--------|-------|

## Interface Contracts (summary — see contracts/ for full specs)

### WatcherDefinition

```typescript
interface WatcherDefinition<TConfig, TEvent> {
  readonly id: string;
  readonly name: string;
  readonly description: string;
  readonly configSchema: TSchema;         // TypeBox schema for config validation
  watch(config: TConfig, signal: AbortSignal): Promise<readonly TEvent[]>;
  extractUri(event: TEvent, config: TConfig): string;      // RFC 3986 URI, any scheme
  extractTags(event: TEvent, config: TConfig): readonly string[];
  readonly hydrators?: readonly HydratorDefinition[];
  readonly sideEffects?: readonly SideEffectDefinition[];
}
```

### HydratorDefinition

```typescript
interface HydratorDefinition<TRaw = unknown, TEnriched = unknown> {
  readonly id: string;
  readonly name: string;
  hydrate(
    entries: readonly StateEntry[],
    signal: AbortSignal
  ): Promise<readonly StateEntry[]>;  // returns same entries with hydratedData populated
}
```

### SideEffectDefinition (Active Record callbacks)

```typescript
type CallbackPhase =
  | 'before_watch'   | 'after_watch'
  | 'before_hydrate' | 'after_hydrate'
  | 'before_steer'   | 'after_steer';

interface SideEffectDefinition {
  readonly id: string;
  readonly phase: CallbackPhase;
  readonly handler: (ctx: SideEffectContext) => Promise<SideEffectResult | void>;
}
```

### StateEntry (core JSONL line type)

```typescript
interface StateEntry {
  readonly type: 'state_entry';
  readonly id: string;                       // UUID v4
  readonly sourceId: string;                 // watcher.id
  readonly sourceUri: string;                // RFC 3986 URI (any scheme)
  readonly timestamp: string;               // ISO 8601
  readonly tags: readonly string[];
  readonly outcomes: Readonly<Record<string, TagOutcome>>;
  readonly data: unknown;                    // raw watcher event
  readonly hydratedData?: unknown;          // post-hydration enrichment
  readonly needsAttention: boolean;
  readonly metadata: StateEntryMetadata;
}
```

## Phased Delivery

### Phase 1 — Core Engine (MVP)
- StateStore (JSONL read/write/query)
- WatcherRegistry + WatcherRunner (no external API calls — filesystem watcher as reference impl)
- HydrationPipeline (serial, ordered)
- SideEffectExecutor (all phases)
- Scheduler (fixed interval, no steering yet)
- TagRegistry (static tags, no per-tag outcome schemas yet)
- Pi extension wired: `session_start`, `session_shutdown`, `/state` command, `watch_query` tool

### Phase 2 — Full Tag Outcomes + Steering
- TagOutcome schemas per TagDefinition
- Steerer (rule-based scoring + needsAttention promotion/demotion)
- Hourly steering trigger in Scheduler
- `/steer` command, `watch_mark_attention` tool
- Optional LLM steering via `pi.sendUserMessage`

### Phase 3 — Reference Watchers + TUI
- Reference watcher: `FilesystemWatcher` (uses `chokidar` or `node:fs/promises`)
- Reference watcher: `GitHubWatcher` (GitHub REST API via personal token)
- TUI widget + footer status
- `watch_trigger_steer` tool
- Full pi package manifest for `pi install`

### Phase 4 — Extended Reference Watchers
- `GmailWatcher` (Gmail API)
- `SlackWatcher` (Slack Web API)
- `BrowserTabWatcher` (Chrome DevTools Protocol / `chrome-remote-interface`)
